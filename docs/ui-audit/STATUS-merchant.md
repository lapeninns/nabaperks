## Bugs found that the audit did not report

1. **The dashboard QR image overflowed its own frame.** `QrFrame` is
   `w-[9.25rem]` with 2px borders, `p-4` and an inner `p-2`, leaving exactly
   6rem of content box — but the image was `size-[7.25rem]` (116px), i.e. 20px
   wider than the box it sat in, spilling past the frame's right edge. Fixed in
   `07af1c3d` by sizing it to 96px, which is both arithmetically correct and the
   size finding 03#12 asked for.
2. **`isPosterPrintPath` covered one of four print routes.** Tent, NFC and
   NFC-square previews kept the shell's sticky mobile header on top of their own
   `.qr-poster-chrome` and scaled their A4 sheet against a viewport the shell had
   already consumed. This is 03#38, but it also became a correctness issue the
   moment the bottom tab bar landed. Fixed in `2f71f030` with unit coverage.
3. **`/app/scan` had no navigation entry at all.** It aliased to Activity in
   `isActiveNavItem`, so the console's most-repeated counter action was reachable
   only by typing the URL or arriving from a members row. Fixed in `9ae7cc7f`
   (and in the tab bar in `2f71f030`).
4. **Finding 03#16's stated premise is wrong.** It argues the members table
   should adopt `DataTable`'s responsive contract to stop rendering every row
   twice. `DataTable`'s own `mobileCard` path renders both the card list and the
   table and hides one with CSS, exactly as the hand-rolled split does, so the
   migration would not remove the double mount. It is still worth doing for the
   other two reasons, but it needs two shared-component changes rather than one.
