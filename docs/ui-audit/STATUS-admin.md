## Deliberately not touched

- **04#54** (panel instructional copy) — a product/copy decision. Trimming five
  panel descriptions risks removing operator-facing procedure; flagged, not guessed.
- **04#60 / 04#26 sticky header** — the table's scroll container is
  `surface-card overflow-hidden` wrapping an `overflow-x-auto` region, so a sticky
  `thead` has no scrollport to stick to. Fixing it is a layout change that needs
  browser proof.
- **04#62 edge fade**, **04#67 StatStrip density** — both are visual judgements
  that need a real browser.
- **04#60 sorting** — a large DataTable API addition consumed live by eight admin
  panels; a half-built sort is worse than none.
- Nothing in `components/ui/*` or `app/globals.css` was edited (shared with other
  lanes). Where a fix needed a shared component's behaviour — the disclosure's
  dashed tone (04#53) — it was pinned from the admin call site instead.

## Contract-shaped decisions

- `tests/contracts/admin-member-lookup` requires `AdminLookupControls` inside the
  privacy workflow panel, so the lookup stayed in the panel rather than moving to
  page level as 04#14 asks. The intent (control adjacent to its results) is met
  because each view now shows one list.
- `tests/unit/github-review-ui-fixes` pins the literal `surface-card grid min-w-0`
  class string on `AdminRecordCard`'s article, and the Tailwind Prettier plugin
  re-sorts any added class into the middle of it — so 04#52's container query
  lives on the field `<dl>` instead. Functionally identical.
- `tests/contracts/dev-route-production-guard` asserts an exact inventory of /dev
  pages. Adding the two index pages (04#71) required adding their paths to that
  inventory; every guard assertion (production `notFound`, noindex robots, /dev
  prefix) is untouched.

## Bug found that the audit missed

`getAdminQrCodes` embedded `merchants(business_name)` while `qr_codes.merchant_id`
is `NOT NULL`, and `getAdminAuditLogs` embeds a nullable merchant. When adding
venue filtering, an unconditional `merchants!inner` on the audit query would have
silently dropped every audit row with no merchant — most of the security actions.
The audit reader therefore switches its embed to `!inner` only when a venue
fragment is supplied.
