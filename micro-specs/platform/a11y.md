# MS-platform-a11y — WCAG 2 A/AA axe sweep across surfaces

## Intent

Every user-facing surface passes an automated WCAG 2 A/AA accessibility audit.
A shared axe-core helper scans each surface for zero violations after hiding the
Next.js dev overlay, so the audit reflects the real product markup, not
dev-only chrome. This is the cross-cutting slice; it depends on the surfaces in
the other specs existing and is the last to be authored.

## Scope (in)

- The shared axe helper (`tests/e2e/helpers/axe.ts`, restored in
  [MS-platform-e2e-harness]) and the a11y spec(s) (`tests/e2e/a11y.spec.ts`).
- Coverage: the public marketing surfaces (`/`, `/pricing`, `/about`,
  `/loyalty-for-pubs`, `/privacy`, `/terms`) and the DB-free
  `/dev/app-harness/*` console lanes (the auth-gated merchant UIs, scanned
  without login).

## Scope (out)

- Fixing individual a11y violations in product components — those land in the
  owning surface's spec. This spec owns the *sweep*, not the remediations. No
  product behaviour change.

## Decisions already made

- The audit uses `@axe-core/playwright` with tags `wcag2a`, `wcag2aa`,
  `wcag21a`, `wcag21aa` via `expectNoAxeViolations(page, label)`.
- The helper hides `nextjs-portal` / the dev overlay before scanning so dev-only
  markup never pollutes the result.
- A11y specs are tagged `@a11y` so `pnpm test:a11y` (`playwright test --grep
  @a11y`) runs exactly the sweep.

## EARS requirements

- **AY-1 (zero violations):** THE axe-core WCAG 2 A/AA scan of each covered
  surface SHALL report zero violations.
- **AY-2 (overlay excluded):** THE sweep SHALL hide the Next.js development
  overlay before scanning so its markup is never audited.
- **AY-3 (coverage):** THE sweep SHALL cover the public marketing surfaces and
  the DB-free `/dev/app-harness/*` console lanes.
- **AY-4 (tagged run):** THE a11y specs SHALL be tagged `@a11y` so `pnpm
  test:a11y` runs only the accessibility sweep.

## Verification method

`pnpm test:a11y` runs the `@a11y`-tagged specs against the dev server;
`tests/e2e/a11y.spec.ts` iterates the covered routes and calls
`expectNoAxeViolations` for each (AY-1/AY-2/AY-3). Because the `/dev/app-harness`
lanes mount the real merchant shells DB-free, the merchant console UIs are
audited without a Supabase login. Run on the same Linux baseline as CI to avoid
platform-specific rendering noise.

## Gates

`pnpm lint` · `pnpm typecheck` · `pnpm test:a11y`.
