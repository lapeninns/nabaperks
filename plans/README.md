# Implementation Plans

Generated by the `improve` skill on 2026-07-03, audited against commit `4a04c141`.
Each plan is self-contained: an executor with **zero context from the audit
session** can run it from the plan file + the repo alone. Read the plan fully
before starting, honor its STOP conditions, and update your row below when done.

This repo is a mature, heavily-audited live product (a 102-agent architecture
audit + multiple perf/UX passes already fixed the big rocks: GDPR erasure,
security headers, CI-runs-tests, OTP hardening). These plans target what those
passes **missed** or what emerged in recently-committed, un-governed code — plus
grounded product direction. Nothing here regresses the verified moat invariants
(one-stamp-per-UK-day, single-use redemption, fail-closed billing, deny-by-default
RLS) — several plans explicitly guard them.

## Findings considered and rejected

Recorded so they aren't re-audited next run:

- **Optimistic reward-activation toggle "leaves the launch gate stale"** —
  REJECTED. `toggleRewardPoolItemActiveAction` (`app/app/card/actions.ts:346-348`)
  calls `revalidatePath("/app/launch")`, and the reward-pool form renders at
  `/app/launch?tab=card`; a Server Action revalidating the current route pushes a
  refreshed RSC payload, so the parent `activeRewardCount` (`loyalty-card-form.tsx:266`)
  re-derives a beat after the optimistic pill. Normal confirmed-optimistic UX, not
  a stuck gate.
- **`check-env.mjs` validates only ~11 of 32 env vars** — REJECTED. The checker
  iterates **every** entry in `config/env-contract.json` (31 entries,
  `scripts/check-env.mjs:80`) and requires each non-`optional` one; the
  runtime-critical secrets (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`,
  `SUPABASE_SERVICE_ROLE_KEY`, `CUSTOMER_SESSION_SECRET`, phone secrets) are in the
  contract and validated by default. `productionRequiredEnvNames` is only the set
  *promoted to required* in the `--profile=production` run, not the whole check.
- **Cron routes fail open when `CRON_SECRET` is unset** — REJECTED (my own initial
  hunch). The guard is fail-*closed*: `if (!secret) return false`
  (`app/api/cron/*/route.ts`). (The separate timing-safe-compare improvement is
  plan 001.)
- **`postcss < 8.5.10` moderate advisory** — NOTED, below plan threshold. Build-time
  only, transitive via `next`, not reachable by request data, severity moderate
  (not high). Add a pnpm `overrides` pin when convenient, or let a `next` bump
  carry it; not a standalone security finding.

## Notes on what was NOT audited

- Runtime/production profiling (CWV/INP, `EXPLAIN ANALYZE`, index *usage* at scale)
  — a source audit can't prove these; the perf plans are query-shape changes that
  don't depend on new indexes, but a schema pass would confirm existing ones.
- The moat RPC SQL bodies and full RLS matrix — prior adversarial verification
  found them strong; the security pass confirmed the app layer feeds them
  correctly but did not re-derive the RLS matrix.
- Exhaustive duplication sweep across all `lib/merchant/*` loaders and every
  Playwright spec.
