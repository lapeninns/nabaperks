## Why this matters

Two small manifest inconsistencies:

1. `shadcn` (the component-generator **CLI**) sits in `dependencies`, so it and
   its transitive tree get installed into every production/CI runtime install
   even though nothing imports it at runtime — it is only invoked via the
   `shadcn` CLI against `components.json`. That bloats prod install time and the
   dependency-audit surface for a package that never runs in prod.
2. `.nvmrc` pins Node **24** (so CI runs Node 24 via `node-version-file: .nvmrc`),
   while `package.json` `engines` says `>=22` and `@types/node` is `^25`. These
   don't contradict (24 satisfies `>=22`), but the version target is spread
   across three values; aligning removes a latent "which Node?" ambiguity.

Both are low-risk hygiene. Do them together because they touch the same manifest.

## Steps

### Step 1: Move `shadcn` from `dependencies` to `devDependencies`

Remove the `"shadcn": "^4.11.0"` line from the `dependencies` object and add it
to the `devDependencies` object (keep alphabetical order there — it will sit
between `prettier-plugin-tailwindcss` and `tailwindcss` or wherever `s` sorts).
Then relock.

**Verify**:
- `pnpm install` → exit 0.
- Confirm placement: `node -e "const p=require('./package.json'); console.log('dep', !!p.dependencies.shadcn, 'dev', !!p.devDependencies.shadcn)"`
  → prints `dep false dev true`.
- `pnpm build` → exit 0 (proves nothing at runtime needed `shadcn`).

### Step 2: Node-version alignment (verify-only; change only if instructed)

This step is deliberately conservative. Do the following **read-only** check and
record the result in your report, but do **not** change `.nvmrc` or `engines`
unless the operator explicitly approves a Node-target change (it affects CI and
every contributor's local runtime):

- Confirm the spread: `.nvmrc` = `24`, `engines.node` = `>=22.0.0`,
  `@types/node` = `^25`.
- Recommended alignment (for the operator to approve): set `engines.node` to
  `>=24.0.0` to match `.nvmrc`/CI, OR change `.nvmrc` to `22` if 22 is the
  intended runtime. Leave `@types/node` at `^25` (or bump to match the chosen
  major) — a dev-only type bump.

If the operator has NOT approved a Node change, leave Step 2 as a documented
recommendation only and proceed. If they HAVE, make the single agreed edit and
re-run `pnpm typecheck` + `pnpm build`.

**Verify** (only if a change was made): `pnpm typecheck && pnpm build` → exit 0.
